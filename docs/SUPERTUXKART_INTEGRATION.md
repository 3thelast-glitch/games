# SuperTuxKart -> NAQLA: native integration plan

## Current status (2026-10-24)

**Source prepared, game NOT integrated / NOT playable in NAQLA.**
A pinned upstream Git submodule is staged at
`native/supertuxkart/stk-code`. The game is deliberately not registered
in `apps/mobile/src/gameLibraryCatalog.ts` or any game routing state; a
non-functional game tile would be misleading.

Upstream repository: https://github.com/supertuxkart/stk-code
Pinned source commit: `2997f192e6876047909d909498dbb4810e5dbb8d`.

## Verified upstream architecture

- Original SuperTuxKart is a C++ 3D kart-racing game with its own native
  renderer and simulation, not a TypeScript/React rules-engine plugin.
- Official upstream has an Android-native build:
  `stk-code/android/ANDROID.md`, `make_deps.sh`,
  `generate_assets.sh`, `make.sh`.
- Upstream Android build needs separately downloaded kart, track, model,
  music and texture data; these are not all in `stk-code`.
- Upstream Android builds require an Android SDK, NDK, native dependencies,
  and asset processing. Its own Android application manifest and activity
  cannot be pasted into a Capacitor app unchanged.
- NAQLA's Android project is generated by `scripts/mobile.mjs`, not
  permanently maintained in `android/`. Native changes must survive
  regeneration.
- The web game library currently assumes JavaScript-rendered pages and
  two-player core rules for server matches. SuperTuxKart does not fit that
  game-engine contract and should remain separate from this server registry.

## Milestone 2: embed in the SAME Android app (not a second APK)

- [ ] Design a native Android module around the upstream C++ runtime, via
      JNI/NDK and an in-app native Activity/view.
- [ ] Resolve Activity lifecycle, OpenGL context, audio, input, full-screen
      orientation, pause/resume, process death, storage, asset extraction
      and back navigation to NAQLA.
- [ ] Resolve Gradle/NDK toolchain versions and package/manifest collisions.
      Avoid importing upstream's standalone `applicationId` and launcher
      manifest directly.
- [ ] Make all native changes reproducibly generated/applied by
      `scripts/mobile.mjs` or an explicitly maintained plugin/module.
- [ ] Verify the original cars, tracks, rules and UI are preserved, rather
      than replacing the game with a JavaScript mockup.
- [ ] Measure size/performance and handle low-end device compatibility.
- [ ] Test cold launch, multiple race sessions, leaving/returning, upgrades,
      clean reinstall and physical hardware game controllers.

## Milestone 3: surface the playable native game in NAQLA

- [ ] Register a genuine mobile-only game route only after Android launch
      actually works. Explain web/iOS support honestly if unavailable.
- [ ] Add a premium thumbnail, Arabic/English game details, a full-screen
      entry flow and an in-game return-to-NAQLA action.
- [ ] Keep the upstream engine's actual modes separate from NAQLA's existing
      two-player turn-based quick match/private-room server. Never claim that
      STK is supported by the existing server-authoritative match protocol.
- [ ] Add native packaging and smoke tests to CI. Verify on real devices
      before enabling it for users.

## Web and iOS

The upstream source checkout does not provide an instantly usable browser
or Capacitor-web game. Web would require a separately maintained supported
port or other real runtime solution; showing a static page is not a port.
iOS needs its own real native packaging and lifecycle integration. Do not
mark either platform supported without builds and gameplay tests.
